# Leviathan transition bar correction

The native victory exposed eight received out-of-range bar values between 09:04:01 and 09:04:08 UTC, ranging from -0.0070563294 to -0.072656415. These remain recorded in the [receipt review items](receipts/review-items.json); they are not passing normalized-bar observations. The earlier controlled suite checked the first phase only at full, three-quarter and exactly half health, so it missed this interval.

The installed Cataclysm 3.33 JAR has SHA256 `371956D0C2E3B56729EE93B955E936875D210E372FE734CDB74326D89EF79875`. Its `The_Leviathan_Entity.tick()` sends `(health - maxHealth / 2) / (maxHealth / 2)` while `getMeltDown()` is false. Crossing half health does not immediately set that flag: the native phase animation must begin after the current move, and its `aiStep()` changes the flag at frame 90. Damage received during that delay makes the first-segment progress negative. After the flag changes, the native bar uses `health / maxHealth` and render type 6.

The installed client `CustomBossBar.drawBar()` multiplies received progress by 183 and draws the fill only when the resulting integer is positive. Render types 5 and 6 choose different artwork; neither interprets negative progress as a special state. Therefore the native empty first-segment appearance is appropriate, but the negative packet value is a normalization defect. No reversed fill or crash is inferred from these samples.

The 1.2.1 correction clamps the argument to the two native `CMBossInfoServer.setProgress(float)` calls inside `tick()` to 0–1 before any packet is broadcast. The exact installed bytecode invokes these calls at offsets 196 and 215. The optional mixin requires exactly two matches. Health, AI, attack selection, movement, phase timing and render-type selection continue through the native code. The empty segment stays empty until the boss itself completes its phase switch.

The targeted controlled regression adds first-phase values just above half, exactly half, just below half and at ten percent health, then executes the native phase code before frame 90 and at frame 90. It checks preserved health, the native mode flag and the native render-type switch as well as progress. Cleanup removes the native orbs emitted by this isolated probe.

The 1.2.1 dedicated server executed all 396 boss-bar assertions successfully at 11:17:22 UTC on 2026-11-05. This includes the 29 added assertions and the original three Leviathan segment checks. The production SHA256 was `53C2399B5040778E76EDE113793AAC6C263A6EEB5779AD52FA80F4D4B0F37C77`, with helper `C1C5ACEC1E30CA930457CB2B3B05448AA06F2C81849A4F8E00BAC4C184E3F598`.

The [fresh natural transition observations](unfinished-leviathan/README.md) now reproduce the critical interval. Received progress was 0 at boss health 547.3194, 538.2994 and 518.09937 HP before the native meltdown flag changed. After the flag changed, health 482.0194 produced progress 0.43819946, matching health divided by 1100. All four values were finite and normalized. These bounded observations preceded a later server stall, so the corrected transition has natural runtime evidence while that encounter remains unfinished.
